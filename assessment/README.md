# Входная диагностика

Цель — выбрать учебные темы и проверить профиль навыков. Это авторский инструмент, а не стандартизированный CEFR-экзамен. Нельзя обещать валидность, точность до подуровня или общий уровень только по проценту правильных ответов.

## Порядок

1. Уточнить цель и режим. Известно: разработка ПО, 30 минут пять дней в неделю. Уровень ещё unknown.
2. Грамматика: 24 вопроса, по четыре на A1–C2. Чтение: шесть коротких текстов, по два вопроса. Аудирование: шесть отдельных текстов, по два вопроса.
3. Можно разделить тест на 2–3 дня. Не использовать переводчик, словарь или ключи. Если не знаете ответ, выберите «Не знаю ответа»; угадывать не нужно. Это явное сообщение о затруднении, а не пропуск. Автоматический расчёт требует все 36 ответов по грамматике/чтению, включая «Не знаю». Незавершённый тест можно оставить черновиком. Помощь или случайные ответы отметить в журнале, их достоверность ниже.
4. Аудирование не подменять чтением. Нет голоса/звука — оставить раздел пустым и провести с партнёром позже. При частично заполненном разделе итог навыка остаётся unknown, ответы сохраняются.
5. Письмо и устная часть — data/assessment.mjs / браузер. Агент оценивает по RUBRICS.md с примерами из ответа. Без доступного аудио произношение и устная плавность unknown.
6. Провести неподготовленное взаимодействие: уточнение, несогласие, пересказ проще. Для C1/C2 добавить длинный незнакомый текст и живое аудио: короткий тест недостаточен.

## Прозрачный алгоритм автоподсказки

Внутри каждого навыка рассматриваются последовательные блоки A1 → C2. Блок поддержан, если отвечены все его вопросы и верно >=75%. При четырёх вопросах это 3/4, при двух — 2/2. «Поддержанная тестом ступень» — последняя непрерывно пройденная. Первая непройденная ступень — учебный старт. Если A1 выполнен менее чем наполовину, старт Pre-A1. Если всё выполнено, старт остаётся C2 для дальнейшей проверки; сертификат не выдаётся.

Раздел неполон → unknown, не нулевой уровень. «Не знаю ответа» считается завершённой попыткой без правильного ответа и добавляет тему для проверки, но не доказывает отсутствие всех навыков этой ступени. В экспорте это индекс, равный длине списка вариантов (4); прежние индексы 0–3 сохраняют смысл. Отдельные неверные ответы добавляют темы ошибок к маршруту. Очень высокие ответы после провала базового блока требуют беседы: возможны случайность, знакомая тема или неоднородный профиль. Два вопроса дают очень грубый сигнал — агент обязан проверить вывод новыми заданиями.

Итоговый план строится по наиболее раннему учебному старту среди известных навыков и добавляет technical modules по зависимостям. Пропущенные ранние prerequisites становятся короткими проверками, не автоматически освоенными модулями. Внесённые ручные оценки влияют на план, но остаются оценками указанного проверяющего, не приложения.

## Повторная диагностика

Сохранить дату, исходные ответы, использованную помощь и качество аудио. Не использовать немедленное повторение тех же вопросов как доказательство роста. Агент готовит параллельные новые задания через 4–6 недель или после существенного этапа. История браузера хранит до 30 попыток; перед длительным обучением делайте экспорт. Ответы и ключи лежат в исходниках открыто — защита от списывания не является задачей проекта.
