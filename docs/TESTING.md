# Проверка проекта

## Автоматические проверки

```powershell
npm run build
npm run check
npm test
node scripts/browser-smoke.mjs
```

Первые три команды не требуют интернета и сторонних пакетов. Check проверяет 40 топиков, 1173 карточки с IPA, 48 вопросов диагностики, наполненные подтемы и их тесты, минимум 10 заданий в каждом новом банке, ключи/критерии, зависимости, актуальность Markdown, локальные ссылки и контрольные суммы двух PDF. Отдельно проверяются 26 букв, 44 позиции выбранной фонемной модели, 12 временных форм, расширенные глагольные таблицы, 32 количественные основы, 31 порядковая форма, 7 дней и 12 месяцев, 36 пар существительных, 12 неисчисляемых значений, четыре указателя и семь притяжательных рядов, семь рядов be и 14 вопросительных групп; семь личных рядов Present Simple, 36 показательных глаголов и 12 выражений частотности; семь рядов Present Continuous, 40 основ для -ing и 12 пар значений; три модели there is/are, 16 количественных конструкций, 20 единиц порции и 22 пространственных отношения. Количество не доказывает полноту: содержательный разбор обязателен отдельно.

Проверка переработки 2026-09-21: Node 22.17.0; сборка, валидация и 81 Node-тест проходят. Обёртка установленного npm 12.0.2 / Volta выдаёт MODULE_NOT_FOUND для npm-prefix.js; это проблема локальной установки npm, не зависимости проекта. Выполнены эквивалентные команды напрямую: `node scripts/build-content.mjs`, `node scripts/validate.mjs`, `node --test`. Сервер также запускается через `node scripts/serve.mjs`. Глобальные версии проект не изменяет.

Browser smoke — проверка в установленном Chromium/Chrome/Edge; можно задать `BROWSER_PATH`. Браузер запускается headless с отдельным временным профилем, без обычных пользовательских данных. ### Общая шкала топиков · 2026-09-22

Сборка, валидация и **93 Node-теста** проходят (12 новых в `test/progress.test.mjs`). Проверены нулевые состояния всех 40 топиков без создания записей, сумма реального объёма разных подтем, только текущие ID и непустые ответы, отличие черновика от отправки, отсутствие прибавки за повторные варианты и отзывы, граница 99/100%, импорт v1/v2 и неизменность исходных данных. Заполнение даже неверных ответов не превращается в mastery; отметка краткой версии не засчитывает расширенную. Счётчик не зависит от времени, карточек и заметок, не закрывает расширенный топик в планировщике.

Браузерный сценарий дополнен проверками:

1. Все 40 топиков имеют шкалу с корректными value/max, доступным названием и описанием; поиск сохраняет правильный счётчик, ID элементов не дублируются. В маршруте используется та же формула.
2. Ввод и очистка ответа обновляют шкалу и счётчик подтемы сразу. Поле и прогресс восстанавливаются после перезагрузки. Черновик теста не даёт отправку; сохранённая попытка добавляет один шаг, открытые ответы остаются «ожидает проверки».
3. Отметка краткого A203 переключает только явно подписанную бинарную шкалу и переживает перезагрузку. Клавиатура раскрывает формулу расширенного топика с видимым фокусом.
4. Отдельная синтетическая фикстура даёт 47%, затем 100% заполнения P01 без подтверждения знаний. Очистка одного ответа показывает 99%; восстановление ответа возвращает 100%.
5. Через настоящие обработчики интерфейса создаётся экспорт Blob, выполняется сброс только изолированного тестового профиля, проверяются нулевые шкалы, затем импортируется тот же JSON через файловое поле. Исходные значения восстанавливаются. Тест перехватывает только сохранение файла на диск и диалог подтверждения; реальные ответы ученика не используются.
6. На ширине 390 px карта, краткий и расширенный топики не растягивают экран. Числа вида «1 / 4» не разрываются. Просмотрены `.artifacts/progress-course-desktop.png`, `progress-topic-desktop.png`, `progress-course-mobile.png`, `progress-topic-mobile.png`, `progress-legacy-mobile.png`.

Для ручной проверки повторите пункты 1–3 на своём ответе, затем экспортируйте резервную копию и сверяйте после импорта. Не сбрасывайте личное состояние без резервной копии. Проверки реального аудио ниже остаются отдельными: этот этап их не подтверждает.

Регрессия боковой панели: на длинной странице результатов примечание не пересекается с меню. При desktop-высоте 600 px панель ограничена высотой окна, последняя ссылка достижима с клавиатуры благодаря внутренней прокрутке. Мобильное меню сохраняет горизонтальную прокрутку. Скриншот: `.artifacts/a101-sidebar-short-desktop.png`.

Регрессия вкладок: разные банки kind=practice имеют различимые подписи. Проверяются «Практика» / «Написание» в A102, «Практика» / «Порции» и «Практика» / «Направление» в A103. Проверены все опубликованные маршруты и разделы, нормализация адреса подтемы, миграция v1/v2 без `navigation`, сохранность прежней закладки, независимые позиции/поля/карточки, ограничения импорта. Реальные обработчики экспорта/сброса/импорта переносят навигацию и черновики.

Ручное повторение:

1. Если сервер уже работал до обновления, остановить его в терминале (`Ctrl+C`) и снова выполнить `node scripts/serve.mjs`: новый allowlist загружается при старте. Не очищать localStorage.
2. В карте установить поиск/уровень, прокрутить; открыть подтему, заполнить ответ и перейти в другой раздел. Меню курса возвращает к подтеме, хлебная крошка карты — к прежним фильтрам и позиции карты.
3. Открыть приложение, ввести поиск; перейти на главную и обратно через меню. Повторить с «Назад/Вперёд» и перезагрузкой. Открытие адреса без hash продолжает последний экран, `#home` явно открывает главную.
4. Проверить незавершённые поля профиля/речи и сторону карточки. Возврат не отправляет тест, не сохраняет оценку профиля/отзыва, не оценивает карточку и не включает микрофон.
5. Экспортировать резервную копию; импортировать и проверить пути/черновики. Не сбрасывать реальное личное состояние без резервной копии.

Просмотрены `.artifacts/navigation-course-desktop.png` и `navigation-speech-mobile.png`; горизонтального переполнения при 390 px нет. Все автоматические действия выполнялись только в отдельном синтетическом профиле. Автоматический перезапуск уже запущенного сервера недоступен в текущей среде; в тесте сервер запускался с обновлённым allowlist.

Ручной сценарий перед использованием нового материала:

1. Если сервер запущен до обновления, перезапустить его через `Ctrl+C` → `node scripts/serve.mjs`; не очищать localStorage. Новые публичные файлы разрешаются при запуске.

## Ручная проверка аудио на компьютере ученика

1. `npm start`, открыть localhost в браузере с поддержкой SpeechRecognition.
2. Открыть речь, выбрать UK/US в профиле. Прослушать образец; убедиться, что выбран английский голос. При отсутствии голоса должно появиться сообщение, а не ложный успех.
3. Без согласия микрофон не запускается. После согласия и разрешения ОС/браузера произнести фразу, остановить; проверить транскрипт.
4. Запретить разрешение — понятная ошибка. Выключить интернет — понятное сообщение или сетевая ошибка, возможность вручную вставить текст сохраняется.
5. Перейти в другой раздел/вкладку — распознавание должно остановиться. При возвращении не включается само.
6. Сравнение текста подписано как сходство слов, не фонетическая оценка. Проговорить числа и сокращения: ASR может представить их иначе.
7. Проверить живой разговор и запись со слушателем. Только этот этап позволяет оценить понятность произношения.

Физический микрофон, слышимое качество TTS и доступность внешней службы нельзя подтвердить тестом с имитацией. До ручного выполнения этих шагов они считаются непроверенными в данной среде.

## Ручная проверка данных

Экспортировать JSON → сохранить резервную копию → импортировать → сверить ответ, карточку и черновик. Импорт заменяет состояние только после проверки и подтверждения. Повреждённый/неподдерживаемый JSON должен быть отклонён без потери текущих данных. «Скачать исходное хранилище» позволяет сохранить непрочитанный исходник при проблеме загрузки. Сброс касается только ключа приложения, не файлов на диске.

В приватном режиме/при запрете localStorage приложение должно сообщить об отсутствии сохранения. При смене порта данные не переносятся автоматически: используйте экспорт/импорт. Никогда не используйте реальные ответы ученика как тестовые фикстуры в Git.
