# Проверка проекта

## Автоматические проверки

```powershell
npm run build
npm run check
npm test
node scripts/browser-smoke.mjs
```

Первые три команды не требуют интернета и сторонних пакетов. Check проверяет 40 топиков, 304 карточки с IPA, 48 вопросов диагностики, наполненные подтемы и их тесты, минимум 10 заданий в каждом новом банке, ключи/критерии, зависимости, актуальность Markdown, локальные ссылки и контрольные суммы двух PDF. Отдельно проверяются 26 букв, 44 позиции выбранной фонемной модели, 12 временных форм, расширенные глагольные таблицы. Количество не доказывает полноту: содержательный разбор обязателен отдельно.

Проверка переработки 2026-09-21: Node 22.17.0; сборка, валидация и 30 Node-тестов проходят. Обёртка установленного npm 12.0.2 / Volta выдаёт MODULE_NOT_FOUND для npm-prefix.js; это проблема локальной установки npm, не зависимости проекта. Выполнены эквивалентные команды напрямую: `node scripts/build-content.mjs`, `node scripts/validate.mjs`, `node --test`. Сервер также запускается через `node scripts/serve.mjs`. Глобальные версии проект не изменяет.

Browser smoke — проверка в установленном Chromium/Chrome/Edge; можно задать `BROWSER_PATH`. Браузер запускается headless с отдельным временным профилем, без обычных пользовательских данных. Проверены: карта → топик → подтема → раздел; черновик и перезагрузка; точное восстановление прокрутки; незавершённый многострочный ответ; отсутствие ключей до отправки; результат по целям и второй вариант; алфавит, звуки и глаголы; переворот карточки клавишей Enter; IPA и отдельная озвучка без оценки знания; диагностика, маршрут, ручная оценка; мобильная ширина 390 px, включая длинные таблицы и задания. Проверяется, что созданный браузером экспорт проходит тот же валидатор импорта.

Скриншоты в ignored `.artifacts/`: home-desktop, topic-desktop, card-desktop, test-review-desktop, home-mobile, topic-mobile, practice-mobile, card-mobile. Визуально проверены читаемость, иерархия, фокус карточки, отделённые органы управления и отсутствие горизонтального переполнения основного экрана. Распознавание **имитируется**: проверяются согласие и обработка результата, не качество службы. В headless озвучивание может сообщать ошибку — воспроизводимый звук не подтверждён. Временные профили содержат только синтетические ответы; их можно удалить вручную после закрытия браузера.

Дополнительно Node-тесты проверяют миграцию v1 → v2 с сохранением прежних свидетельств, независимость объёма очереди от минут/дней, невозможность зачесть открытый ответ автоматически, историю вариантов, основания ручной оценки, требование прослушанного аудио, защиту от неизвестных ID и повреждённого места продолжения.

CI выполняет build, проверку отсутствия незакоммиченной разницы генерируемых модулей, check и test. Браузер и микрофон в CI не проверяются.

## Ручная проверка аудио на компьютере ученика

1. `npm start`, открыть localhost в браузере с поддержкой SpeechRecognition.
2. Открыть речь, выбрать UK/US в профиле. Прослушать образец; убедиться, что выбран английский голос. При отсутствии голоса должно появиться сообщение, а не ложный успех.
3. Без согласия микрофон не запускается. После согласия и разрешения ОС/браузера произнести фразу, остановить; проверить транскрипт.
4. Запретить разрешение — понятная ошибка. Выключить интернет — понятное сообщение или сетевая ошибка, возможность вручную вставить текст сохраняется.
5. Перейти в другой раздел/вкладку — распознавание должно остановиться. При возвращении не включается само.
6. Сравнение текста подписано как сходство слов, не фонетическая оценка. Проговорить числа и сокращения: ASR может представить их иначе.
7. Проверить живой разговор и запись со слушателем. Только этот этап позволяет оценить понятность произношения.

Физический микрофон, слышимое качество TTS и доступность внешней службы нельзя подтвердить тестом с имитацией. До ручного выполнения этих шагов они считаются непроверенными в данной среде.

## Ручная проверка данных

Экспортировать JSON → сохранить резервную копию → импортировать → сверить ответ, карточку и черновик. Импорт заменяет состояние только после проверки и подтверждения. Повреждённый/неподдерживаемый JSON должен быть отклонён без потери текущих данных. «Скачать исходное хранилище» позволяет сохранить непрочитанный исходник при проблеме загрузки. Сброс касается только ключа приложения, не файлов на диске.

В приватном режиме/при запрете localStorage приложение должно сообщить об отсутствии сохранения. При смене порта данные не переносятся автоматически: используйте экспорт/импорт. Никогда не используйте реальные ответы ученика как тестовые фикстуры в Git.
