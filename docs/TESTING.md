# Проверка проекта

## Автоматические проверки

```powershell
npm run build
npm run check
npm test
node scripts/browser-smoke.mjs
```

Первые три команды не требуют интернета и сторонних пакетов. Check проверяет 40 топиков, 837 карточек с IPA, 48 вопросов диагностики, наполненные подтемы и их тесты, минимум 10 заданий в каждом новом банке, ключи/критерии, зависимости, актуальность Markdown, локальные ссылки и контрольные суммы двух PDF. Отдельно проверяются 26 букв, 44 позиции выбранной фонемной модели, 12 временных форм, расширенные глагольные таблицы, 32 количественные основы, 31 порядковая форма, 7 дней и 12 месяцев, 36 пар существительных, 12 неисчисляемых значений, четыре указателя и семь притяжательных рядов, семь рядов be и 14 вопросительных групп; семь личных рядов Present Simple, 36 показательных глаголов и 12 выражений частотности; семь рядов Present Continuous, 40 основ для -ing и 12 пар значений; три модели there is/are, 16 количественных конструкций, 20 единиц порции и 22 пространственных отношения. Количество не доказывает полноту: содержательный разбор обязателен отдельно.

Проверка переработки 2026-09-21: Node 22.17.0; сборка, валидация и 81 Node-тест проходят. Обёртка установленного npm 12.0.2 / Volta выдаёт MODULE_NOT_FOUND для npm-prefix.js; это проблема локальной установки npm, не зависимости проекта. Выполнены эквивалентные команды напрямую: `node scripts/build-content.mjs`, `node scripts/validate.mjs`, `node --test`. Сервер также запускается через `node scripts/serve.mjs`. Глобальные версии проект не изменяет.

Browser smoke — проверка в установленном Chromium/Chrome/Edge; можно задать `BROWSER_PATH`. Браузер запускается headless с отдельным временным профилем, без обычных пользовательских данных. Проверены: карта → топик → подтема → раздел; черновик и перезагрузка; точное восстановление прокрутки; незавершённый многострочный ответ; отсутствие ключей до отправки; результат по целям и второй вариант; алфавит, звуки, глаголы и числовой справочник; P02 с тремя подтемами, различение 17/1.7, сохранение десятичного ответа и многострочного тестового черновика; P03 с четырьмя подтемами, a/an по звуку, число владельцев и сохранение student’s/students’, длинный черновик, итог и история нового варианта, обе новые таблицы; P04 с тремя подтемами, ролью отвечающего, тремя допустимыми отрицательными формами, различием false/not stated, длинным черновиком, историей варианта B и справочником be; переворот карточки клавишей Enter; IPA и отдельная озвучка без оценки знания; диагностика, маршрут, ручная оценка; мобильная ширина 390 px, включая длинные таблицы и задания. Проверяется, что созданный браузером экспорт проходит тот же валидатор импорта.

Скриншоты в ignored `.artifacts/`: home-desktop, topic-desktop, card-desktop, test-review-desktop, home-mobile, topic-mobile, practice-mobile, card-mobile, p02-topic-desktop, p02-reference-desktop, p02-reading-mobile, p02-reference-mobile, p03-topic-desktop, p03-review-desktop, p03-reference-desktop, p03-reading-mobile, p03-reference-mobile, p04-topic-desktop, p04-review-desktop, p04-reference-desktop, p04-reading-mobile, p04-reference-mobile. Визуально проверены читаемость, иерархия, фокус карточки, отделённые органы управления и отсутствие горизонтального переполнения основного экрана. Распознавание **имитируется**: проверяются согласие и обработка результата, не качество службы. В headless озвучивание может сообщать ошибку — воспроизводимый звук не подтверждён. Временные профили содержат только синтетические ответы; их можно удалить вручную после закрытия браузера.

Для P02 отдельно сверяются независимые ожидаемые значения чисел и часов, past/to, teen/ty, начальные нули, десятичная точка, суффиксы порядковых чисел, полнота заявленного календарного набора, новые карточки и совместимость старого состояния P02. Для P03 — независимые ключи форм, C/U, артиклей, указателей и владельцев; апостроф различает смысл, открытый ответ не зачтён даже при совпадении с образцом; старые заметки/SRS сохранены. Для P04 проверены согласование по главному слову, смена you/I/we, полярность отрицательного вопроса, whose/who’s, смысл вопросительных групп и неизвестных данных, допустимые сокращения, адресная практика по ошибке, полные письменные образцы, старые записи и история теста. Число слов образца проверяется как качество авторского материала, не используется для автоматического зачёта ответа ученика. Парсер авторских заданий отклоняет лишние поля вместо молчаливой потери текста.

## Ручная проверка аудио на компьютере ученика

1. `npm start`, открыть localhost в браузере с поддержкой SpeechRecognition.
2. Открыть речь, выбрать UK/US в профиле. Прослушать образец; убедиться, что выбран английский голос. При отсутствии голоса должно появиться сообщение, а не ложный успех.
3. Без согласия микрофон не запускается. После согласия и разрешения ОС/браузера произнести фразу, остановить; проверить транскрипт.
4. Запретить разрешение — понятная ошибка. Выключить интернет — понятное сообщение или сетевая ошибка, возможность вручную вставить текст сохраняется.
5. Перейти в другой раздел/вкладку — распознавание должно остановиться. При возвращении не включается само.
6. Сравнение текста подписано как сходство слов, не фонетическая оценка. Проговорить числа и сокращения: ASR может представить их иначе.
7. Проверить живой разговор и запись со слушателем. Только этот этап позволяет оценить понятность произношения.

Физический микрофон, слышимое качество TTS и доступность внешней службы нельзя подтвердить тестом с имитацией. До ручного выполнения этих шагов они считаются непроверенными в данной среде.

## Ручная проверка данных

Экспортировать JSON → сохранить резервную копию → импортировать → сверить ответ, карточку и черновик. Импорт заменяет состояние только после проверки и подтверждения. Повреждённый/неподдерживаемый JSON должен быть отклонён без потери текущих данных. «Скачать исходное хранилище» позволяет сохранить непрочитанный исходник при проблеме загрузки. Сброс касается только ключа приложения, не файлов на диске.

В приватном режиме/при запрете localStorage приложение должно сообщить об отсутствии сохранения. При смене порта данные не переносятся автоматически: используйте экспорт/импорт. Никогда не используйте реальные ответы ученика как тестовые фикстуры в Git.
